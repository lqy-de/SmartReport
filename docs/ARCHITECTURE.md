# SmartReport 第一阶段架构

项目沿用任务书的界面、控制器、服务、解析、存储、校验和导出分层。相关职责以模块或包组织在 `app/`。原始报表、应用数据和打包产物不进入源码仓库。公开回归测试使用程序生成的虚构样本。

## 第一阶段导入流程

| 步骤 | 模块 | 行为 |
| --- | --- | --- |
| 选择来源 | `ui/import_page.py` | 默认打开文件导入页。首个按钮使用 `QFileDialog.getExistingDirectory`，第二个按钮选择多个文件。接受本地文件及目录拖拽，同时保留显式 ZIP 入口。 |
| 后台执行 | `controllers.py` | 一次启动一个 `QThread`。扫描、SHA-256、解包读取、解析和批次写入在后台串行进行。使用 Qt 信号更新扫描状态、文件及页进度和每个处理结果。 |
| 查找输入 | `services/importer.py` | 先处理目录，再处理单选文件。递归识别 PDF、XLS、XLSX，记录类型和排除计数。跟踪源根、相对路径、父目录、批次与时间。 |
| 解析输入 | `parsers/` | PDF 使用 PyMuPDF 原生文字和坐标表格规则。工作簿通过 xlrd 或 openpyxl 读取后作为独立参考表。 |
| 检查和写入 | `validators.py`、`database.py` | 检查内容哈希、表头、分数范围、明细与原表差异和更正提示。每个文件的来源、考试、明细和问题在同一个事务提交。 |
| 查询和分组 | `ui/grades.py` | 以导入根和完整相对文件夹构建树，支持选中父节点查询所有子目录。跨来源的同名目录分开，批次和其它条件可叠加使用。 |
| 输出 | `exporters.py` | 选择字段和记录范围。XLSX 字符串按文本保存，CSV 和 TXT 对可能被表格程序视作公式的文本做前缀处理。写完后记录输出路径，供后续递归排除。 |

选择目录和后台线程的接口分别参见 [Qt QFileDialog](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QFileDialog.html) 和 [Qt QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)。应用将 PyMuPDF 调用集中到同一个导入工作线程。 [PyMuPDF 并发说明](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html)

## 导入状态和恢复

- 路径访问失败、文件损坏、版式未识别及相同文件跳过分别记录。遇到坏文件继续处理本批次的其余文件。
- 目录联接、符号链接、程序数据、虚拟环境、缓存和应用记录的导出文件会被排除。排除目录只计一次，不访问其内容。
- ZIP 仅通过兼容入口或直接拖入该文件读取，成员在内存中读取。处理前检查成员名、路径穿越、重复成员、符号链接、压缩比、成员数与展开体积。单文件解析上限为 128 MiB。
- 若发生批次级错误，已提交的文件和成绩仍可查看。本阶段以重新选择该目录并使用默认跳过策略的方式续做。
- 原始成绩、扣分列和明细保留，人工核准的得分和状态另有修改记录。表头不完整、零分、缺失、识别失败分别记录。

## 第一阶段范围

交付文件夹优先导入、PDF 样本解析、SQLite、批次文件结果、按目录分组、成绩搜索、明细和得分核准、两种模板及三种导出格式。项目目前使用文件导入和成绩管理两个页面，导出入口位于成绩管理。工作台统计、专门的对账工作区、科目配置、统计分析、模板管理、OCR、AI 和其余导出格式留在后续阶段。
